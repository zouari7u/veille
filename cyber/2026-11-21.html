Quatre nouvelles failles exploitées activement ajoutées au catalogue de la CISA

L'agence américaine a intégré des vulnérabilités touchant Apache Roller, Cisco Expressway, SAP NetWeaver et VMware vCenter suite à des signalements d'exploitation active.

Repères

  • CVE : CVE-2025-42884, CVE-2026-76466, CVE-2026-123890, CVE-2026-102764
  • Score CVSS : 9.3
  • Date limite fédérale : 23 novembre 2026
  • Acteur ou groupe : Armory Castle (UNC5221)

La Cybersecurity and Infrastructure Security Agency a complété son catalogue des failles exploitées (KEV) avec quatre vulnérabilités touchant diverses solutions logicielles d'entreprise. Les mainteneurs d'Apache Roller ont confirmé que leur composant subissait des attaques actives sans toutefois préciser les vecteurs exacts. De son côté, la faille affectant VMware vCenter a été signalée par la société F6 lors d'une compromission sur un réseau tiers, tandis que celle concernant Cisco Expressway a été associée aux agissements d'un groupe d'espionnage informatique lié à la Chine.

Concernant cette dernière intrusion, l'acteur malveillant a combiné l'exploitation de la vulnérabilité avec un autre défaut présent dans BeyondTrust Remote Support pour déployer des portes dérobées persistantes. Les agences fédérales américaines ont reçu l'instruction d'appliquer les correctifs nécessaires pour l'ensemble de ces quatre points d'entrée avant le 23 novembre 2026.

PrioritaireCRITIQUEPHP-FPM Request Smuggling

Une faille de contrebande de requêtes PHP-FPM menace nginx et Apache

Un défaut dans le traitement des corps de requêtes HTTP non lus permet à un attaquant distant d'exécuter du code arbitraire.

Repères

  • Score CVSS : 9.2 CRITICAL
  • Produits affectés : nginx, Apache, PHP-FPM

Un problème critique de type request smuggling (technique consistant à exploiter les divergences d'interprétation des requêtes HTTP entre un proxy et un serveur dorsal) a été identifié dans PHP-FPM. Le mécanisme ne rejette pas la partie non lue d'un corps de requête HTTP lors de la fermeture de la connexion lorsque l'application ouvre l'entrée php://input sans en lire la totalité. Si le frontal réutilise les connexions vers le dorsal, configuration activée par des directives spécifiques sur nginx ou Apache, PHP-FPM peut interpréter les octets restants comme une nouvelle requête FastCGI.

Un attaquant non authentique peut ainsi employer une requête multipart/form-data forgée pour injecter des paramètres arbitraires tels que SCRIPT_FILENAME ou REMOTE_ADDR. Cette manipulation conduit à des compromissions de services web hébergeant des applications PHP vulnérables.

PrioritaireCRITIQUEApache Tomcat

Multiples vulnérabilités critiques d'authentification et de chiffrement dans Tomcat

Plusieurs failles de sécurité majeures affectent la gestion des clusters, l'interception de chiffrement et le traitement des exceptions d'authentification.

Repères

  • Score CVSS : 9.8 CRITICAL, 9.1 CRITICAL
  • Produits affectés : Apache Tomcat 11.0.0-M1 à 11.0.29, 10.1.0-M1 à 10.1.62, 9.0.0.M1 à 124, et versions 8.5/7.0 EOL
  • Version corrigée : 11.0.30, 10.1.63, 9.0.125

Plusieurs bulletins critiques ciblent Apache Tomcat à travers différentes versions. Un premier défaut dans l'intercepteur de chiffrement EncryptInterceptor expose des entrées sensibles à l'absence de vérification d'intégrité ou à du trafic en clair. Un second problème d'échange de clés sans authentification d'entité permet à un nœud non authentique de rejoindre un cluster sécurisé par TLS 1.3 et TLS-PSK. Enfin, un défaut de nettoyage après une exception d'authentification provoque l'envoi erroné d'un code de succès HTTP 200 au lieu d'une erreur HTTP 500.

Ces vulnérabilités touchent de nombreuses branches de Tomcat, y compris des versions en fin de vie (EOL). Il est fortement conseillé de migrer vers les versions les plus récentes ou d'adapter les protocoles de chiffrement utilisés pour les communications de clusters.

HIGHnginx 1.30.7

Publication de la version stable nginx 1.30.7 corrigeant de multiples failles

Cette mise à jour majeure résout plusieurs vulnérabilités de corruption mémoire, de boucles infinies et de contournements de validation.

Repères

  • CVE : CVE-2026-123634, CVE-2026-123007, CVE-2026-121810, CVE-2026-123633, CVE-2026-118899, CVE-2026-113425, CVE-2026-125283, CVE-2026-120967, CVE-2026-123640
  • Version corrigée : nginx 1.30.7

Le projet nginx a publié sa version stable 1.30.7 intégrant des correctifs pour un ensemble de vulnérabilités. Le correctif traite notamment des anomalies de type use-after-free localisées dans le résolveur, le module HTTP/3, le module HTTP/2 et le module de proxy de messagerie. Des problèmes de corruption mémoire liés au contrôle de flux HTTP/2 et de dépassement de tampon lors de l'utilisation combinée des directives alias et try_files ont également été résolus.

La mise à jour corrige en outre une boucle infinie lors de la lecture du corps d'une requête client via TLS 1.3, ainsi que des défauts de validation dans le module stream, incluant un contournement SNI lors de la validation de certificats clients et une insuffisance de vérification dans stream ssl_preread.

CRITIQUEPostgres Enterprise Manager

Failles critiques d'exécution de code et d'élévation de privilèges dans PEM

Des rôles surprivilégiés et l'absence de chemin de recherche sécurisé dans des fonctions de base de données permettent une prise de contrôle.

Repères

  • Score CVSS : 9.4 CRITICAL
  • Produits affectés : Postgres Enterprise Manager (antérieur à 10.6.1)
  • Version corrigée : PEM 10.6.1

Deux vulnérabilités critiques de niveau CVSS 9.4 affectent Postgres Enterprise Manager (PEM). La première concerne le rôle pem_agent hérité par tous les agents PEM, qui s'avère membre des rôles système pg_read_server_files et pg_write_server_files sur la base dorsale. Un attaquant contrôlant un hôte surveillé et son certificat peut lire ou écrire des fichiers sur le serveur PEM en tant qu'utilisateur du système d'exploitation, lui permettant d'émettre de faux certificats d'agents. La seconde faille réside dans des fonctions exécutées avec les privilèges du créateur (SECURITY DEFINER) qui omettent de définir un search_path sécurisé, permettant à un utilisateur authentique de soumettre des objets malveillants pour exécuter du code arbitraire avec les privilèges du superutilisateur.

Ces comportements sont corrigés à partir de la version PEM 10.6.1, où les agents ne détiennent plus ces rôles et où les fonctions utilisent un chemin de recherche fixe.

Recommandation : Mettre à jour Postgres Enterprise Manager vers la version 10.6.1 ou ultérieure pour restreindre les privilèges des agents et sécuriser le chemin de recherche.

HIGHGPGME / GnuPG

Une vulnérabilité de double libération mémoire découverte dans la bibliothèque GPGME

Une clé OpenPGP malveillante dotée d'un identifiant anormalement long déclenche un bug critique de corruption mémoire dans GPGME.

Repères

  • CVE : CVE-2026-129975
  • Produits affectés : Logiciels utilisant GPGME versions antérieures à 2.3.0
  • Version corrigée : GPGME 2.3.1

Un défaut de double libération mémoire (double free), suivi sous l'identifiant CVE-2026-129975, touche la bibliothèque GPGME utilisée par de nombreux programmes pour interagir avec GnuPG. Le problème survient au sein des routines de lecture de statuts et de listes de clés lorsque le traitement d'une entrée anormalement longue provoque une erreur intermédiaire. Cela laisse un pointeur vers une zone mémoire déjà libérée, entraînant une seconde libération non intentionnelle lors du nettoyage.

Cette anomalie expose divers clients de messagerie, clients XMPP, ainsi que des solutions comme Samba et Gpg4win, qui intègrent ou lient cette bibliothèque. Bien qu'aucune attaque n'ait été recensée au moment de l'alerte, une exécution de code à distance ne peut être totalement exclue par les mainteneurs.

Recommandation : Mettre à jour la bibliothèque GPGME vers la version 2.3.1 dans l'ensemble des applications dépendantes.
Sources : The Hacker News
